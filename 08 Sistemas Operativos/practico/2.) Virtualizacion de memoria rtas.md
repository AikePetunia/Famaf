Para este ejercicio debemos saber que en memoria virtual, para cada programa tenes 3 partes importantes.

El Code: El codigo del programa propio (o sea sus instrucciones) tienen que vivir en algun lado, por lo tanto vive en el espacio de direcciones (adress space), aca entran variables globales, codigo ejecutables (funciones como main). El code DEBE ser estatico, se pone en los kb mas bajos (0-1kb) por que no se movera de ahi y es "facil de manejar".

Heap: Crece hacia abajo, es el que maneja la Memoria dinamica, memoria manejada por el usuario, arreglos, punteros, mallocs, free, etc.

Stack: Crece hacia arriba, maneja las variables del programa, rastrea en donde estan las funciones, pasar parametros y devolver valores.

Una variable nunca puede mudar de stack a heap o de heap a stack. Menos cambiar a code.

```c

	s += a[i]+b[i];

}
```

Ejercicio 6. Distinguir relocalizaci´on est´atica y relocalizaci´on din´amica

La relocalizacion estatica es a nivel software/loadtime: El cargador del sistema operativo reescribe las direcciones fisicas directamente en el codigo binario al momento de cargarlo en la ram. No requiere soporte de la MMU,no eofrece proteccion de memoria ni permite mover el proce de lugar una vez cargado.
Relocalizacion dinamica es a nivel hardware o run time: la mmu traduce las direcciones virtuales a fisicas en tiempo de ejecucion mediante base y bounds. Mantiene el binario intacto, prinda proteccion por hardware (con segmentation fault) y permite al so mover procesos en la ram en cauqluier momento

La **Segmentación NO es relocalización estática**. De hecho, la Segmentación es **Relocalización Dinámica pura por hardware**.

Ejercicio 10. La TLB de una computadora con una pagetable de un nivel tiene una eficiencia del 95 %. Obtener un valor de la TLB toma 10ns. La memoria principal tarda 120ns. ¿Cu´al es el tiempo promedio para completar una operaci´on de memoria teniendo en cuenta que se usa tabla de p´aginas lineal?

La TLB de una pc con una pagetable de un nivel tiene una eficencia del 95%.
-> Obtener un valor de la tlb toma 10ns
-> La RAM tarda 120ns. 

si no esta en la tlb, es un miss y debe ir a buscar la entrada correspondiente a la tabla de paginas que esta guardada en la ram fisica (120ns adicionales)
si esta en la TLB, obtiene el pfn al instante en el tiempo que tarda la tlb (10ns)
Una vez que la MMU ya tiene la dirección física resuelta, la CPU finalmente accede a la RAM física para **leer o escribir el dato o la instrucción** deseada ($120\text{ ns}$).

o sea que si hay hit (o sea, tlb NO falla): tarda 10 ns (tlb) + 120ns (ram) = 130ns 

si la tlb da miss, que es el 5% de las veces. 
seria 10 ns (no esta) + 120ns (hace un viaje a la ram para leer la entrada correspondiente) + 120 ns (accedo dato real)

Para obtener el tiempo promedio ponderado considerando la probabilidad de hit ($0{,}95$) y miss ($0{,}05$):

$$\text{EAT} = (\text{Hit Rate} \times \text{Tiempo}_{\text{Hit}}) + (\text{Miss Rate} \times \text{Tiempo}_{\text{Miss}})$$
$$\text{EAT} = (0{,}95 \times 130\text{ ns}) + (0{,}05 \times 250\text{ ns})$$
$$\text{EAT} = 123{,}5\text{ ns} + 12{,}5\text{ ns} = 136\text{ ns}$$
