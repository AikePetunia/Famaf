2)
Como se hace uso de hilos, que comparten codigo, variables y heap dentro de la memoria, además de que cada Thread tiene su stack y estado propio. El walltime es menor que el cputime porque el proceso utiliza multiples hilos que pueden ejecutarse simultaneamente en diferentes nucleos. El walltime mide el tiempo real transcurrido, mientras que el cputime acumula el tiempo de cpu utilizado por todos sus hilos. Por eso, al ejecutarse varios hilos en paralelo, la suma de sus tiempos de cpu puede superar el tiempo real transcurrido.

int main(int argc, char ** argv) { 
	if (argc<=1) return 0; 
	
	int rc = fork(); 
	if (rc<0) {
		return -1;
	} else if (0==rc) {

		execvp(argv[0], argv); 
	}

open -> abre o crea un archivo, y devuelve un file descriptor (fd)

dup crea una copia de un archivo existente abierto. 
a dup le tenes que pasar un numero entero, para que el sistema operativo identifique un archivo o recurso abierto.

`dup(fd)` crea otro file descriptor que referencia la misma apertura del archivo/recurso que `fd`.
**crea otra referencia al mismo recurso abierto**.

Escenario 1, Blocked -> Ready:
Los procesos que pasan a `Blocked` no pueden volver a `Ready` cuando termina la espera, por lo que quedan bloqueados indefinidamente y no pueden volver a competir por la CPU.

Escenario 2, Ready -> Running.
Un proceso que está `Ready` nunca puede pasar a `Running`, por lo que ningún proceso listo puede obtener CPU.

Escenario 3, Running -> Ready.
destruye el **scheduling preventivo** (preemptive scheduling) que permite  al SO quitarle la CPU a un proceso que está ejecutándose y darle la CPU a otro

Escenario 4, Running -> Blocked.
no habría momentos de esperas en que respondan los I/O
