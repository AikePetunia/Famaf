Ejercicio 4. Un programa define la variable int x=100 detro de main() y hace fork(). 

(a) ¿Cu´anto vale x en el proceso hijo? 

La syscall fork(), duplica un proceso actual (y su contexto anterior a la syscall fork(), tales como variables u otras cosas), ademas de que la llamada puede retornar:
fid == -1 si hubo algún error en la llamada fork()
fid == 0 si estoy en el proceso hijo.
fid > 0 si aún estoy en el proceso padre.
 
Trabajar dentro de un if() para cada valor de fid devuelto es lo mejor que hay para manejar contextos distintos en cada proceso nuevo. 

El creador del fork, se le llama proceso padre y el proceso creado a partir del padre se llama hijo, siendo este proceso hijo casi similar al proceso padre, causando algo como:

```c 
int x = 100; // <- contexto anterior
fork();  // <- Proceso padre crea su hijo
printf("hola, %d", x); // <- Esto lo ejecutaran el proceso padre y el hijo (ademas de la variable x)
```

Por lo tanto, ambos programas queda x=100.

(b) ¿Qu´e le pasa a la variable cuando el proceso padre y el proceso hijo le cambian de valor? 

Reitero que la syscall fork(), hace una duplicación del programa, una copia casi igual al proceso origianl, por lo tanto en un inicio pueden ser identicos, pero el contexto de cada proceso puede cambiar radicalmente.

Asumiendo que ya el problema se plantea luego de hacer un fork(), cada proceso tiene su propio contexto, por lo tanto el modificar una varialbe dentro del hijo o el padre no tendría por que afectar al otro, pero todo esto dentro de una buena practica. Pues:

```c
int x = 100; // <- contexto anterior
int fid = fork();  // <- Proceso padre crea su hijo
printf("valor de x:", %d) // 100 (Esto se imprimira 2 veces; en el hijo y en el padre)
if (fid == -1) {
	// error idk
} else if (fid == 0) {
	printf("VALOR DE X ANTES DE CAMBIARLO EN HIJO", %d); // 100
	x = 101; // este cambio solo existe en el hijo
	printf("valor x: %d", x); // 101
} else if (fid > 0) {
	printf("VALOR DE X ANTES DE CAMBIARLO EN padre", %d); // 100
	x = 102; // este cambio solo existe en el padre 
	printf("valor x: %d", x); // 102
}

```

(c) Contestar nuevamente las preguntas si el compilador genera ASM colocando esta variable en un registro del microprocesador.

(a): `x` sigue valiendo 100 en el hijo. La syscall `fork()` guarda el contexto completo de registros de la CPU en la estructura del proceso (`PCB` / `trapframe`) y lo duplica para el hijo. Por ende, el hijo restaura los mismos valores de registros.

(b): El comportamiento **no cambia en absoluto**. Cada proceso tiene su propio estado de registros virtualizado por el mecanismo de _Context Switch_. Cuando el hijo modifica el registro, solo altera su propio juego de registros; el padre conserva intacto el suyo cuando vuelve a tomar la CPU.

```c
 int main(int argc, char ** argv) { 
	 if (0 < --argc) { 
		 argv[argc] = NULL; 
		 execvp(argv[0], argv); 
	 } 
	 return 0;
 }
```
Notemos que en la entrada, se hace que `0 < --argc`, que reduce la cantidad de argumentos (argc, arguemnt count) en 1, quitando asi 1 solo argumento, y luego verificando asi, la cantidad de argumentos.

En args tenemos que:
argv[0] == comando
argv[resto] = argumentos
argc[argc] = NULL // Esto se hace para marcar el final del comando. 
Por lo tanto, lo que se hace es validar si un comando es valido, para luego marcar su final y ejecutarlo. Recordar que luego de execvp solo se imprime si hay algun error.

argv[argc-1] = NULL; esto hace que un arguemnto como null provocando 
execvp(argv[0], argv); // que ESTO reejecuta el programa

El programa se ejecuta recursivamente a si mismo, en cada pasa elimina el ultimo arguemnto escribiendo NULL al final de argv[argc] = NULL, hasta que no quedan mas arguemtnos (0 < -- argtc da falso) y termina con return 0. 


```c
int main(int argc, char ** argv) { 
	if (argc<=1) return 0; 
	
	int rc = fork(); 
	if (rc<0) {
		return -1;
	} else if (0==rc) {
		return 0; 
	} else { 
		argv[argc-1] = NULL; 
		execvp(argv[0], argv); 
	}
```
Primero, está verificando que la cantidad de argumentos sea mayor que 1. 
Por ejemplo, si tuvieramos un comando con 3 argumentos, el primer if daría válido y el programa seguiria. 
Si tuvieramos unicamente un comando, o sea argc == 1, el programa no sigue y corta en el return 0;

Luego, se hace un fork, guardando su valor en rc.
`int rc = fork();`
Debemos de hacer una distincion antes de seguir analizando la ejecucion:
si fork == -1, dio un error al duplicar el proceso actual
si fork == 0, estamos en el hijo
si fork > 0, estamos en el proceso padre. 

Ahora, sabemos que si da error, retorna -1.
Si estoy en el proceso hijo, lo retorna con 0 cortando su ejecucion.
Si estoy en el proceso padre, en el último argumento asigno null como argumento de ejecucion.
Sepamos que el último argumento se le esta cambiando a un null:
`argv[argc-1] = NULL; `

Luego, el padre llama a `execvp(argv[0], argv)`. **Esto es lo que provoca la recursión:** como `argv[0]` es el propio programa, el proceso padre sobrescribe su memoria y se relanza a sí mismo desde el `main`, pero ahora con una lista de argumentos que tiene un elemento menos.

-O_WRONLY : El archivo solo se abre en modo escritura, no en lectura 
-O_TRUNC: Setea los bytes del archivo en 0, o sea borra el contenido viejo si es que el archivo existe, pero tiene contenido

La syscall de dup() (y sus familiares, dup2(), dup3()), permiten "Recablear" entradas de file descriptors y salidas de comandos en archivos o parecidos, siendo su sintaxis:

dup2(int oldfd, int newfd);
